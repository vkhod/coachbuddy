# CoachBuddy — Workspace Agent Rules (`AGENTS.md`)

**CoachBuddy** is a polyglot microservices & multi-agent CrossFit coaching platform (WOD preparation, 2-phase non-repetitive warm-ups, 4-tier movement scaling, minute-by-minute class timelines, and QR code session sharing). It builds a plan to read; there is no live class timer or Floor Mode.

For deeper architectural rationale and system diagrams, consult [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## 2. Core Cross-Service Invariants (Always Follow)

1. **Same Behaviour in Every Environment (No Canned Plans)**:
   - Development and production run the same code paths. A plan is only ever produced by the real agents calling a real LLM with a real key. There is no zero-key, demo or hybrid mode.
   - Never substitute canned, regex-generated or locally re-computed content when an LLM call, an MCP tool call or another service fails. Mark the affected step or plan section as failed, with the reason, so the coach can retry.
   - Fakes belong only in automated tests: recorded LLM responses (fixtures) and test doubles inside the test suites, never in application code paths.
   - `agents-python` has no fallbacks since Phase 2 step 8. The local plan builder in `web/pwa-nextjs/src/lib/api.ts` is removed in Phase 3; do not add new ones.
   - The databases (Postgres, MongoDB, Redis) are required in every environment; `compose.yml` provides them locally. `gateway-go` has no in-memory or file fallback (removed in Phase 2 step 6) and `mcp-rust` does not start without MongoDB (step 7). Do not add new ones. In-memory fakes belong only in tests.
   - Secrets have no defaults in code or compose files. Services refuse to start when a required secret is missing.
2. **BYOK API Key Security (`AES-256-GCM`)**:
   - User LLM keys (the providers in `services/gateway-go/internal/modelcatalog/models.json`: `gemini`, `openai`, `anthropic`) are encrypted at rest in `gateway-go` using AES-256-GCM with unique 12-byte nonces.
   - Never log, persist in plaintext, or return raw API keys to the frontend—always return masked previews (`sk-p••••9x8Z`) and only pass decrypted keys ephemerally over internal requests to `agents-python`.
3. **One Contract, Generated Types (`schema/`)**:
   - `schema/*.schema.json` (JSON Schema 2020-12) is the single source of truth for every payload between `pwa-nextjs`, `gateway-go`, `agents-python` and `mcp-rust`. Field names are `camelCase`.
   - The contract types in each service are generated by `scripts/gen-schema` and committed: `web/pwa-nextjs/src/lib/contract/`, `services/agents-python/app/contract/` (except `rules.py`), `services/gateway-go/internal/contract/`, `services/mcp-rust/src/contract.rs`. Never edit them by hand: change the schema, add an example under `schema/examples/`, run `scripts/gen-schema`, commit both.
   - Rules across fields that JSON Schema cannot express live in `services/agents-python/app/contract/rules.py`; timeline arithmetic lives only in mcp-rust (`verify_timeline_math`).
   - CI job `schema (contract)` fails when the generated files differ from the schema. See `schema/README.md`.
   - The older hand-written copies (Go `internal/models` plan types, the interfaces in `web/pwa-nextjs/src/lib/api.ts`) are replaced as each service moves to the new contract in Phase 2 and 3; do not extend them.
4. **Agent Customization Maintenance**:
   - When adding a new microservice, MCP tool, or major architectural pattern, update this root `AGENTS.md` and the corresponding service-level `AGENTS.md`.

## 3. Common Build & Verification Commands

- **Full Stack (Docker Compose)** (needs a filled-in `.env`, see `.env.example`):
  ```bash
  docker compose -f compose.yml -f compose.dev.yml up --build
  ```
- **Contract (`schema/`)**: regenerate the types after any schema change (tool setup in `schema/README.md`):
  ```bash
  scripts/gen-schema && npm test --prefix schema
  ```
- **Go Gateway (`services/gateway-go`)**:
  ```bash
  cd services/gateway-go && go test -v ./...
  ```
- **Python Orchestrator (`services/agents-python`)**:
  ```bash
  cd services/agents-python && pip install --require-hashes -r requirements.txt -r requirements-dev.txt && pytest -v
  ```
- **Rust MCP Server (`services/mcp-rust`)**:
  ```bash
  cd services/mcp-rust && cargo fmt --check && cargo test --locked
  ```
- **Next.js PWA (`web/pwa-nextjs`)**:
  ```bash
  cd web/pwa-nextjs && npm run build
  ```

## 4. Pull Requests, CI and Dependencies

- **Required checks on `main`** (ruleset `protect-main`): `agents-python (Python)`, `compose files`, `gateway-go (Go)`, `mcp-rust (Rust)`, `pwa-nextjs (Next.js)`, `schema (contract)`, `secret scan (gitleaks)`. The Docker build jobs in `docker-build.yml` (`changed services`, `docker build (<service>)`) are not required on purpose, because they are path-filtered.
- Every change goes through a pull request; the owner reviews and merges. One planned step per pull request, with the decisions made in it listed in the body for review.
- **Tests never call a real LLM.** They use recorded answers (`services/agents-python/tests/recordings/`). Live checks are manual, with a call budget agreed in advance.
- **Dependabot** opens grouped pull requests every Monday (`.github/dependabot.yml`):
  - Language runtimes (`golang`, `python`, `rust`, `node`) move only together with their CI pin and lock file, by hand. `requirements.txt` is locked for Python 3.12.
  - `google-adk`, `litellm` and `mcp` move together, by hand, after reading ADK's release notes.
  - When a grouped pull request mixes good and bad bumps, take the good ones by hand in a separate pull request and close the grouped one (as in #14).
